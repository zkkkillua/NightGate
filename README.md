# 收尾（NightGate）

面向使用者的安装、首次设置与故障排查说明见 [中文使用指南](USER-GUIDE.zh-CN.md)。

“收尾”是面向 Windows 11 的早睡承诺装置：它提前阻止新的电脑娱乐，给已经开始的
游戏或视频留下安全善后时间，并在约定时刻锁屏。它的边界是：**防冲动，不防蓄意拆除**。
管理员始终可以停止服务或卸载程序；它不是反篡改安全产品，也**不诊断或治疗失眠**。

## 工作方式与威胁模型

工作日晚间依次经过 `Free`、`LastStart/Grace`、`LandingLocked` 和 `Morning`。每个游戏达到
自身的一局时长截止时间后，程序会阻止新启动该游戏，并允许已记录的当前游戏善后；Chrome
扩展允许当前视频结束但阻止下一集。故障统一安全放行，不断网、不修改电源计划、不强杀
门禁前已有进程、不锁死账户。

0.3.17 给所有倒计时浮窗加上向外扩散的光晕和四边散射粒子。每轮重新随机生成间隔、数量、
角度、速度、光环圈数，以及圆点、菱形、光线形态，不播放一段固定重复的图样；这不保证用户
不会适应提示。动画仅在浮窗可见时以 20 fps 运行，关闭系统动画或启用高对比度时改用静态外圈。
卡片正文尺寸不变：常规 380×148 DIP 外加每边 48 DIP 特效区域，游戏卡 560×240 DIP 外加
每边 64 DIP；透明边缘计入每 12 秒随机换位与屏幕工作区避让。特效仍点击穿透、不抢焦点，
不改变剩余时间、例外或锁屏截止。Chrome 继续使用 0.1.5。

0.3.16 加强游戏收尾提示：有效“最后开局”提醒开始后，若已配置的游戏主进程仍在运行，
会显示 560×240 DIP 的大号倒计时浮窗，比原来的 380×148 DIP 例外卡片更醒目。自定义长局
可随现有最后开局提醒一起提前触发，但不会被更早的“如果—那么”计划卡触发。浮窗显示
当前时间（HH:mm:ss）、锁屏截止时间与剩余时间；关闭游戏后恢复原来的最后 10 分钟提示规则。
新旧倒计时浮窗均每 12 秒在前台窗口所在显示器的工作区随机明显换位，避开任务栏，不抢焦点、
鼠标点击穿透。游戏检测每 3 秒只读进行一次，仅匹配同一用户、同一会话中已配置 Game 规则的
主程序完整路径；语音工具、辅助程序或同名异路径进程不会单独触发大号提示。移动或系统时间
变化不会延长单调倒计时，视觉层故障也不影响门禁或锁屏。Chrome 仍为 0.1.5，本次未改浏览器逻辑。

0.3.15 修复桌面端退出后 Chrome 仍继续拦截的问题。桌面端现在通过 80 秒单调时钟租约声明
保护会话存活：托盘确认退出会立即结束租约；崩溃、任务管理器强退、服务重启或睡眠恢复时，
缺失或过期的租约一律安全放行；重新打开程序会从服务保存的当晚阶段恢复保护，不会重置例外。
Chrome 扩展 0.1.5 还会在保留拦截页或展示新拦截页前实时复核策略，因此退出后不再等待旧的
45 秒浏览器租约。普通媒体上报和非受限网站不会增加额外轮询。

0.3.14 修复锁屏覆盖层中的例外请求反馈：团队救场被服务接受后会立即取消旧的 10 秒重新
锁屏倒计时，不再依赖下一次后台轮询；若因 168 小时冷却或当前游戏快照不可用而被拒绝，
锁屏页会直接显示原因，并给出新的 10 秒阅读时间。请求确认期间最多延后 25 秒，仍有硬性
重锁上限；紧急解锁、娱乐再用及最终锁屏语义不变。

0.3.13 不再在 21:00 打断用户：计划卡延后到“默认最后开局”和当晚已生效游戏最早截止时间
中较早者的前 30 分钟。最后 10 分钟以及团队救场、紧急解锁和娱乐再用改用被动倒计时卡片
（0.3.16 起按上述规则移动）；娱乐再用不可续期，冷静期明确显示“冷静至”或娱乐窗口开始时间。卡片
不激活、不进任务栏、点击穿透，最后 2 分钟在原卡片内加强颜色。视觉层故障与锁屏、
进程门禁和 Chrome 保护隔离；同一倒计时不会被旧策略、系统时间回拨或界面重启延长。

程序只用于降低深夜临时反悔的概率。拥有管理员权限的电脑所有者能够绕过它，这是明确的
产品限制，不是隐藏的保证。

## 构建与测试

从干净克隆构建前，准备 x64 Windows 11、精确版本的 **.NET SDK 10.0.301**（仅安装运行时不够），
以及 **Node.js 24**（当前验证环境为 24.19.0）。SDK 与 Node 可安装在系统 PATH 中，不需要安装
Codex，也不需要复制作者的 `work/` 或缓存目录。首次还原需要能访问 NuGet.org；WPF 和使用
Windows Installer COM 的测试必须在 Windows 上执行。

在仓库根目录使用 Windows PowerShell 5.1 或 PowerShell 7，先构建并测试源码：

```powershell
.\scripts\Restore.ps1
.\scripts\Test.ps1 -SkipRestore
.\scripts\Build.ps1 -SkipRestore
```

脚本在存在 `work/.dotnet/dotnet.exe` 时优先使用它，否则使用系统 PATH 中的 SDK；`global.json`
禁止自动换用其他版本。Node 可通过 `NIGHTGATE_NODE` 指定，否则查找可用的配套或系统 Node。
`work/dotnet-home`、`work/.nuget/packages` 会自动生成，不属于源码。默认还原保留 `NuGet.Config`
中的在线源，即使本地存在 `work/nuget-feed` 也不会自动切到离线模式。

只有已经准备好**完整依赖源**时，才在当前 PowerShell 中显式设置
`$env:NIGHTGATE_OFFLINE_RESTORE = '1'` 进行纯离线还原；设为 `'0'` 或清除此环境变量可恢复默认。
仅有下面三个运行时包不足以完成全部项目的离线还原。全部构建步骤为 Release、x64/win-x64、
确定性构建并将警告视为错误。默认验证不会安装服务、注册 Chrome、启动生产程序、锁屏或操作
真实计划任务。

正式发布只接受真正的 self-contained `win-x64`。`work/nuget-feed` 必须包含精确 10.0.9 版本的
三个官方 runtime pack（NETCore、WindowsDesktop、AspNetCore）；脚本会核对 nuspec 身份、执行
`dotnet nuget verify --all`、记录 SHA-512，并在缺包、签名失败或内容不符时停止。不会从本机
`shared` runtime 反向制作同名 Microsoft 包。`-ForcePrivateRuntimeFallback` 仅保留给显式诊断，
其产物标记为 `releaseEligible=false`，默认验证会拒绝，不能作为正式 MSI 发布。

制作正式安装包是额外步骤。先从官方 NuGet 来源下载以下原始签名包到一个本地目录：

- `Microsoft.NETCore.App.Runtime.win-x64.10.0.9.nupkg`
- `Microsoft.WindowsDesktop.App.Runtime.win-x64.10.0.9.nupkg`
- `Microsoft.AspNetCore.App.Runtime.win-x64.10.0.9.nupkg`

完成上述源码构建与测试后，导入并验证这些包，再发布：

```powershell
.\scripts\Import-OfficialRuntimePacks.ps1 -SourceDirectory 'C:\path\official-runtime-packs'
.\scripts\Publish.ps1 -SkipBuild
.\scripts\Package.ps1 -SkipPublish
.\scripts\Verify.ps1 -SkipPipeline
```

请将示例下载目录换成实际位置。导入时仍必须通过身份和签名验证；不要提交 SDK、NuGet 包、
`work/`、`artifacts/`、`outputs/`、`bin/obj` 或安装状态到源码仓库。测试依赖的探针源码位于
`tests/Shared/InstalledStateProbe.cs`，随仓库提交，不依赖本机 `work/` 中的副本。

## 安装

`outputs/NightGate-x64.msi` 是首选的 x64 安装包；`installer/NightGate.wxs` 是要求显式提供
ProductVersion 和 ProductCode 的 WiX v4 模板。打包脚本按 ProductVersion 稳定派生 ProductCode，
在 ZIP 中生成身份已展开的审计源，并将它的 ProductVersion、ProductCode、UpgradeCode 与实际
MSI 逐项核对。该源在当前流程中只是 authored-only 证据，没有编译，也不与已只读验证的 MSI
混称为等价产物。MSI 精确要求 x64 Windows 11 build 22000 或更高版本。发布物的服务配置只含
固定占位符，不含构建电脑 SID；首次安装时才读取 Windows Installer 的 `UserSID`，验证它确实
是普通 Windows 账户 SID、写入服务配置并设置 LocalService/该用户 ACL。目标 SID 随后保存在
仅 SYSTEM 和 Administrators 可访问的机器级安装状态中；维修、升级和卸载均读取这个安装时
SID，不会改用发起操作的当前账户。

写入该用户的登录启动值和 Chrome 本地宿主值前，安装事务会保存“值是否存在、类型和原始值”；
安装、维修或升级失败时逐项恢复，成功卸载也恢复安装前原值。每个产品版本有稳定 ProductCode，
不同版本通过固定 UpgradeCode 做主升级并阻止降级；每次重新生成 MSI 都使用新的 PackageCode。
请从实际使用 NightGate 的那个 Windows 账户启动首次安装；SYSTEM 静默首装或 LocalService
身份会被安全拒绝。

0.3.17 安装后可从公共桌面的“收尾”、开始菜单的“收尾 NightGate”或通知区域托盘图标打开。
第一次打开显示五步向导；后台服务暂不可用时，界面会明确显示安全放行状态并提供重试，不会让
不可用的旧数据继续保存。0.3.17 可直接覆盖 0.1.0、0.2.0、0.2.1、0.2.2、0.3.0、0.3.1、0.3.2、0.3.3、0.3.4、0.3.5、0.3.6、0.3.7、0.3.8、0.3.9、0.3.10、0.3.11、0.3.12、0.3.13、0.3.14、0.3.15 或 0.3.16，升级沿用固定 UpgradeCode，并保留
`C:\ProgramData\NightGate` 中的当前状态和历史。当前交付流程只生成和静态验证 MSI，不会替用户
自动安装、维修或卸载；升级前请先正常退出旧桌面端，再手工双击新版 MSI。

ZIP 仍是可审计的备用安装路径。先解压 `outputs/NightGate-win-x64.zip`，再从提升权限的
PowerShell 运行：

```powershell
.\installer\Install-NightGate.ps1 -SourcePath C:\解压目录\NightGate -WhatIf
.\installer\Install-NightGate.ps1 -SourcePath C:\解压目录\NightGate
```

备用脚本先用 `-WhatIf` 查看计划。它捕获当前交互桌面用户的规范 SID，只写入 NightGate 自有的
Program Files/ProgramData、`NightGate.LocalService`、该 SID 的登录启动值和 Chrome 本地宿主
键。发布阶段保留 `appsettings.sample.json` 的固定 SID 占位符，安装阶段再通过当前 WTS 桌面会话
确认目标 SID；空 SID 或 LocalService SID 会被拒绝。配置文件 ACL 明确允许 LocalService 读取，
但不会把服务进程或安装进程身份冒充为桌面用户。服务默认登记但不立即启动；需要立刻启动时
显式添加 `-StartService`。

对于 Chrome 本地宿主，ZIP 脚本会分别读取并保存该 SID 的 32 位和 64 位注册表视图中的原默认值
（含原始值类型）。随后才向两个视图写入 NightGate 清单；任一后续安装步骤失败时会恢复这两个值。
卸载会精确恢复保存的值，而非删除同名用户值。早期 ZIP 安装记录没有这份双视图快照；为避免猜测
所有权，卸载这类旧记录时不会修改 Chrome 本地宿主注册表值。

## 卸载

MSI 的标准卸载入口是“Windows 设置 → 应用 → 已安装的应用 → 收尾 NightGate”。ZIP 备用安装
路径可使用下列脚本，提升权限后先预演，再执行：

```powershell
.\installer\Uninstall-NightGate.ps1 -WhatIf
.\installer\Uninstall-NightGate.ps1
```

卸载只反转 `install-state.json` 记录的服务和注册值，并移除 NightGate 程序目录。默认保留
ProgramData、历史和安装记录；只有用户明确添加 `-RemoveApplicationData` 才删除这些数据。
没有反卸载机制。

## 恢复与旧关机任务

程序不会删除或改写旧关机任务。首次设置时，“设置与向导 → 旧自动关机任务”会只读扫描
调用 `shutdown.exe` 的计划任务，并逐项显示；默认全部不勾选。用户明确勾选后，程序先把任务
路径、完整动作指纹和原启用状态保存到本机数据库，再按同一指纹停用，并重新读取 Windows 中
的实际状态；只有回读确认后才显示为已停用。任务需要管理员权限时，Windows 会弹出一次账户
控制确认；取消后任务仍会显示，可重新勾选重试。任务内容已经变化、记录无法持久化或系统接口
不可用时一律不改动；操作中断后会根据已保存记录安全续完，不会刷新或扩大授权范围。

如需恢复，在同一页面选择“恢复此前停用的旧任务”。程序只恢复由自己记录且内容仍匹配的任务；
恢复失败时保留记录供稍后重试。也可以由管理员在“任务计划程序”中手工重新启用。旧手机闹钟
不由 Windows 程序操作，只通过 iPhone 清单手工关闭或恢复。

0.3.3/0.3.8 只保存了动作级旧指纹。若这类任务已经停用后又经历桌面端重启或升级，程序无法再
证明当前触发器、运行账户和其余定义就是停用当时的定义，因此会继续保持任务停用并拒绝自动恢复；
这不是任务重新启用。用户确实需要恢复时，应在 Windows“任务计划程序”中核对完整定义后手工启用。
当前版本新建立的迁移记录使用包含完整任务定义的组合指纹，不依赖该旧版兼容路径。

如果服务或数据库异常，程序安全放行。无法正常卸载时，管理员可依据
`%ProgramData%\NightGate\install-state.json` 查看本次安装实际登记的项目；不要扫描或批量
删除名字相似的系统项。

## Chrome

ZIP 包含 `chrome-extension` 解压扩展。打开 `chrome://extensions`，启用开发者模式，选择
“加载已解压的扩展程序”，指向该目录。固定公钥导出的扩展 ID 必须是
`eefgemhlhbdodhlgjmicnoifhclhdgmm`。安装器为同一 SID 写入本地宿主注册；它不会强制安装
扩展或使用企业策略。测试普通窗口与当前 Chrome 资料；若需要无痕模式，必须由用户在扩展
详情中明确允许，否则桌面端应显示“网页保护降级”。

加载扩展后还必须打开其“扩展程序选项”，选择与桌面端规则相同的网站、保存，并接受
Chrome 的可选网站访问权限提示。桌面端的首次向导和 Chrome 设置页提供固定扩展 ID 的
选项页按钮；若无法自动打开，则显示 `chrome://extensions → 详细信息 → 扩展程序选项`
的手动路径。未完成网站授权时扩展应安全放行并保持降级状态。
0.3.17 继续使用扩展 `0.1.5`；若已经是此版本，无需因本次浮窗更新重新授权。若仍运行 0.1.4，请到 `chrome://extensions` 对“收尾”点击一次“重新加载”，随后回到桌面端确认版本为 `0.1.5`。原有网站授权会保留，无需重新勾选；旧扩展的核心退出放行仍然有效，但拦截页可能最多等待旧的 45 秒租约，重新加载后才具备立即复核。

## iPhone

Windows 不能远程替用户修改 Apple 设置。每次晋级时，手工同步“健康”的睡眠计划、睡眠专注
以及“屏幕使用时间 → 停用时间”，并开启“停用期间阻止使用”。电话、时钟、必要联系人、
验证器、交通、支付和健康工具保持允许；Safari 不加入始终允许。密码保留 Apple 官方恢复
路径，NightGate 不保存 Apple 凭据。

## 隐私

本地事件仅记录时间、事件类型和网站类别，不记录页面标题、完整浏览历史或原始网址。原始
事件默认保留 90 天。用户可以清除历史，但当前夜间状态和例外令牌不会因此重置。数据留在
受 ACL 保护的本机 ProgramData；首版没有云同步。

## 限制

- 首版仅支持一台 x64 Windows 11、一个 Windows 登录账户、一个 Chrome 资料和一部 iPhone。
- 不包含其他浏览器、自研 iOS 客户端、金钱押注、内核驱动、断网或反卸载。
- 正式 MSI/ZIP 必须是真正的 .NET self-contained；离线源缺少官方签名 runtime pack 时会停止，
  不会自动生成可安装的降级发布物。显式私有 runtime 模式只用于诊断且不能通过正式验收。
- 未通过真实 Windows 会话验收前，不应把自动化测试等同于服务、WTS、锁屏和 Chrome 的实机证明。
- 混合 DPI 倒计时布局必须在真实 Windows 会话中另行验收：至少覆盖前台显示器位于负坐标、跨屏切换且缩放不同、竖向任务栏，以及大号浮窗随机换位后仍完整可见；布局计算测试和单一测试机探针不能替代这项检查。
- 独占全屏游戏可能遮住普通 Windows 置顶浮窗；可使用无边框全屏或窗口模式。0.3.17 的移动浮窗与扩散特效尚未完成安装后的真实游戏实机验收，不保证独占全屏可见。
- 随机特效只避免固定图样循环，不保证持续吸引注意力，也不替代对游戏显示效果和系统动画偏好的实机检查。

仓库中的 `installer/Test-NightGateMsiLifecycle.ps1` 是可选的实机生命周期脚本，只能在可回滚的
专用 Win11 虚拟机快照中显式添加 `-RunLifecycle` 执行；它会真实安装、维修和卸载 MSI。
`-PreviousProductVersion` 可选 `0.3.15` 或 `0.3.16`（默认），并会核对传入旧 MSI 的真实版本。若安装了
Windows SDK，还可传入 `msival2.exe` 和 ICE cube 做额外校验。默认 `scripts/Verify.ps1` 只重开
MSI 做只读结构检查，绝不把结构检查写成“已实机安装”。

## 手工验收

在专用测试账户和可恢复的 Win11 测试机上执行，先备份现有设置：

1. 首选在目标账户运行 MSI；若测试备用脚本，先运行 `-WhatIf`，确认只出现 NightGate 自有
   路径、服务和两个该 SID 注册位置。
2. 安装后确认服务账户为 LocalService；重新登录确认托盘启动，且不会修改电源或网络设置。
3. 从门禁前启动测试游戏，确认可善后；门禁后再开一个测试程序，确认只处理新实例。
4. 在已选择的网站播放视频，确认当前项可结束、下一项被拦截；停用扩展后应显示降级。
5. 锁屏、重新登录、睡眠/唤醒和回拨时间，确认例外次数不会刷新。
6. 测试三类例外的冷静期、次数和到期；紧急解锁原因应留在本地隐私安全事件中。
7. 在 iPhone 限制娱乐后，逐一确认电话、验证码、支付、交通和健康工具仍能使用。
8. 运行卸载 `-WhatIf`，确认不会提及旧关机任务或非 NightGate 数据；默认卸载后历史仍在。
9. 配置一个可安全退出的测试游戏，在有效最后开局提醒后确认大号浮窗显示当前时间、锁屏截止与倒计时；关闭游戏后确认恢复最后 10 分钟规则，语音工具或同名异路径程序不能单独触发。
10. 检查新旧浮窗每 12 秒明显换位、完整位于前台显示器工作区且不抢焦点；跨屏、混合 DPI、任务栏位置变化或回拨时间后，倒计时不得被延长。此项应另在真实游戏的窗口及无边框全屏模式中确认。
11. 检查所有倒计时卡片的光晕与粒子每轮有变化，正文仍清晰；换位时透明特效边缘也不得越出工作区。隐藏卡片后动画停止，关闭系统动画或开启高对比度后仅显示静态外圈；这些变化不得影响鼠标穿透、剩余时间或锁屏。
