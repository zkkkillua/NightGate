# 0.3.15：桌面退出后 Chrome 安全放行

## 问题

桌面端从托盘退出后，`NightGate.LocalService` 仍在运行。Chrome Native Host 继续从服务读取
`blocked` 策略并每 30 秒续租，因此扩展会在 Windows 进程门禁已经停止后继续拦截网站。
`DeliberateBypass` 只是当晚结果标记，不能作为永久停用策略；重新打开桌面端应恢复保护。

## 契约

- 只有活跃的桌面保护会话可以授权 Chrome 限制策略。
- 桌面端每次启动生成新的 32 位小写十六进制会话 ID。
- 桌面策略读取使用 `getDesktopPolicy`，读取成功前先建立或续订 80 秒单调时钟租约。
- Native Host 继续使用 `getPolicy`，不能借由浏览器流量续订桌面租约。
- 托盘确认退出时，桌面端先停止策略轮询，再以最多 1 秒发送 `endDesktopSession`。
- 已结束会话的延迟请求不能复活租约；旧会话也不能结束较新的会话。
- 崩溃、强退、睡眠后长时间未恢复或服务重启时，租约缺失或过期，Chrome 一律安全放行。
- 租约不写入 SQLite，不受系统时间回拨影响；服务重启自然清空。
- 已结束的会话 ID 在当前服务进程生命周期内持续失效，防止很早以前的延迟请求在多次重启桌面端后重新取得控制权；服务重启会自然清空这些随机令牌。

## Chrome 即时释放

服务在桌面会话缺失、过期或结束后：

- `getPolicy` 返回 `enforcementEnabled=false`、`policy=null` 的降级放行结果；
- `recordBrowserEvent` 与 `recordChromeHealth` 返回严格的 `{status:"degraded"}`，且不写数据库、
  不污染全局服务健康状态。

扩展 0.1.5 在继续保留拦截页、或准备为受限站点展示新拦截页之前，会主动刷新一次 Native
Host 策略。若服务已经放行或通信失败，扩展立即清除限制；普通媒体观察和非受限网站不增加
额外请求。

## 验收

- 窗口右上角关闭只隐藏到托盘，租约继续续订，Chrome 保护不变。
- 托盘确认退出后，下一次 Chrome 策略读取不可执行限制，新导航与已有拦截页立即放行。
- 任务管理器强退后，不执行退出命令也会在 80 秒内放行。
- 重新打开桌面端后创建新会话并恢复当前阶段，不重置例外和冷静期。
- 系统时间回拨不会延长租约；旧会话的结束或延迟续租不会影响新会话。
